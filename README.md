# زيارات السلامة والجودة — منصة تسجيل زيارات التدقيق الميداني

تطبيق ويب تقدّمي (PWA) مستقل لتسجيل زيارات التدقيق الميداني للسلامة والجودة: بيانات الزيارة، عدد غير محدود من الملاحظات/المخالفات لكل زيارة، صور، والموقع الجغرافي (GPS) تلقائيًا.

مبني بمعمارية مُدارة بالكامل: React (Vite) + Supabase (قاعدة بيانات PostgreSQL + تخزين ملفات + مصادقة + API جاهز)، بلا أي خادم يُدار يدويًا. راجع وثيقة "توصية معمارية" في مشروع Claude للتفاصيل الكاملة وخارطة الطريق.

## 1) إنشاء حساب ومشروع Supabase (خطوة يقوم بها المستخدم بنفسه)

هذه الخطوة تتطلب إنشاء حساب، ولذلك يجب تنفيذها من طرفك مباشرة:

1. اذهب إلى [supabase.com](https://supabase.com) وأنشئ حسابًا (يمكن تسجيل الدخول مباشرة بحساب Microsoft أو GitHub أو بريد إلكتروني).
2. من لوحة التحكم، أنشئ مشروعًا جديدًا (New Project) — اختر اسمًا مناسبًا مثل `visits-jeddah`، وكلمة مرور قوية لقاعدة البيانات (احتفظ بها في مكان آمن)، والمنطقة الأقرب (مثل Frankfurt/Bahrain إن وُجدت لتقليل التأخير).
3. بعد إنشاء المشروع، اذهب إلى **Settings → Billing** واختر خطة **Pro (25$/شهر)** — ضرورية لتفادي حدود الخطة المجانية (تعطّل المشروع بعد أسبوع من الخمول، وسعة تخزين صور محدودة بـ1 جيجابايت لا تكفي حجم الاستخدام الحقيقي).
4. من **Settings → API**، انسخ القيمتين:
   - `Project URL` → تُوضع في `VITE_SUPABASE_URL`
   - `anon public` key → تُوضع في `VITE_SUPABASE_ANON_KEY`

## 2) تطبيق مخطط قاعدة البيانات

من **SQL Editor** في لوحة تحكم Supabase، نفّذ الملفين بالترتيب (نسخ/لصق كل ملف كاملًا وتشغيله):

1. `supabase/migrations/0001_init.sql` — الجداول (الزيارات، البنود، القوائم المرجعية، كتالوج المخالفات) والصلاحيات.
2. `supabase/migrations/0002_storage.sql` — مكان تخزين الصور وصلاحيات الرفع/القراءة.

(بعد تثبيت مشروعك، يُفضَّل استخدام [Supabase CLI](https://supabase.com/docs/guides/local-development) لتطبيق ملفات الترحيل (migrations) تلقائيًا بدل النسخ اليدوي، خصوصًا عند إضافة تعديلات لاحقة على المخطط.)

## 3) تعبئة كتالوج المخالفات (اختياري لكن مهم)

انقل بيانات جدول "اسم المخالفة (كتالوج)" من ملف الإكسل الحالي إلى جدول `violation_catalog` (عبر SQL Editor أو Table Editor في Supabase) حتى تعمل ميزة "الاختيار من الكتالوج" في نموذج إضافة المخالفات بنفس الكتالوج المعتمد حاليًا.

## 4) إعداد المشروع محليًا

```bash
cp .env.example .env.local
# ضع فيه VITE_SUPABASE_URL و VITE_SUPABASE_ANON_KEY الحقيقيين

npm install
npm run dev       # تشغيل محلي للتطوير
npm run build     # بناء نسخة الإنتاج في مجلد dist/
npm run preview   # معاينة نسخة الإنتاج محليًا
```

## 5) إنشاء أول حساب مستخدم (مهندس/راصد)

من **Authentication → Users** في لوحة تحكم Supabase، أضف مستخدمًا يدويًا (بريد إلكتروني + كلمة مرور)، أو فعّل دعوات البريد الإلكتروني للمستخدمين الجدد. عند إنشاء أي مستخدم، يُنشأ له تلقائيًا صف في جدول `profiles` (عبر Trigger مُعرَّف في المخطط).

## 6) النشر (Hosting)

استضافة الواجهة مجانية بالكامل على أي من:
- [Cloudflare Pages](https://pages.cloudflare.com/) — اربط مستودع الكود، أمر البناء `npm run build`، مجلد الإخراج `dist`.
- [Vercel](https://vercel.com/) — يكتشف إعدادات Vite تلقائيًا.

أضف متغيرات البيئة (`VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`) في إعدادات المشروع على منصة الاستضافة قبل أول نشر.

## 7) الخطوات اللاحقة (خارطة الطريق)

- **نسخة المتجر (لاحقًا)**: تغليف هذا التطبيق عبر [Capacitor](https://capacitorjs.com/docs/web/progressive-web-apps) لنشره على App Store/Google Play دون إعادة بناء الكود.
- **جسر المزامنة مع الإكسل/داشبورد qs**: دالة مُجدوَلة (Supabase Edge Function + Cron) تكتب السجلات الجديدة من هذه القاعدة إلى ملف الإكسل الحالي على SharePoint عبر Microsoft Graph API — تُبنى بعد استقرار الاستخدام الفعلي.

## بنية المشروع

```
src/
  lib/            عميل Supabase، الأنواع، المصادقة، القوائم المرجعية
  hooks/          useGeolocation (تحديد الموقع الجغرافي)
  components/     مكوّنات مشتركة (رفع الصور، القوائم المنسدلة، الترويسة)
  pages/          شاشات التطبيق (تسجيل الدخول، قائمة الزيارات، زيارة جديدة، تفاصيل الزيارة)
supabase/
  migrations/     ملفات SQL لإنشاء المخطط والتخزين
```
